《余生未寄》优化方案与版本路线图
设计评审稿 · 2026-10-08 · 依据：你与 GPT 的审核稿、策划书 V2.0、TapTap 开发者中心公开文档
边界说明： 你给的仓库链接我这边打不开（检索不到，可能是私有库），所以代码、截图、提交记录没有亲自核对。GPT 审核稿里关于代码的判断，我按「可信但待实测」处理，核实动作都放进了 Phase 0。平台条款是我查过官方公开页面后整理的，已附来源；条款会变，以 TapTap 后台为准，也不构成法律意见。
一、评审结论
方向对，但问题定义偏窄。 保留 rc.2 工程、不重写十章、先冻结视觉标准再批量出图，这三条我完全同意。但审核稿把问题定义成「界面与策划书不一致」，我认为真正的缺口是：游戏还没有一个能被截图、能被记住的招牌画面，也没有一套可复用的互动模板。视觉升级要服务这两件事，而不是逐条对齐策划书。
最大风险不是美术难，而是三件事发现得太晚： TapTap 容器与合规（目前排在最后）、全篇文本质量（排在 rc.5）、美术资产总量（策划书没有封顶）。我把三者全部前置到 Phase 0。
美术策略改为「物件优先、面容克制」。 少画脸，多做物件和空间；正脸只出现在剧情照片（天然允许不完美）和少量关键 CG 里。这同时降低跨年龄一致性、包体、素材审核三类风险，也呼应「记忆不可靠」的主题。
阅读页采用「场景窗＋纸面＋年代皮肤」，不做全屏背景叠文字。一套模板、两套皮肤、有限场景库，成本可控。
互动只做五个模板（调查、照片、信件、手机、批注式记忆），数据驱动、可跳过、失败安全。「批注式记忆重构」是本作最有辨识度的招牌互动。
路线重排： Phase 0 取证与前置验证 → Phase 1 标准冻结 → rc.3 门面与阅读层 → rc.4 互动模板 → rc.5 全篇铺开与编辑 → 1.0.0 发布验收。每一步都有通过或不通过的硬门槛，以及回退点。
明确不做： 全屏立绘、逐句配音、数值条、粒子与故障特效、自由文本输入、广告与商城、每章独立场景。

3.2 视觉语言：物件优先、面容克制
画面主角是物件与空间；人物以背影、手、侧影、局部入画。
正脸只出现在三处：剧情照片（失焦、过曝、颗粒、日期戳都是合理的不完美）、关键 CG（全篇≤8 张）、结局卡。
需要跨年龄一致的角色（周叙 17/30/47，许知夏 17/成年）：先做「是不是同一个人」盲测（≥5 人，通过线 80%）；不通过的一律降级为面容克制。
记忆清晰度＝细节层（可选，先在第 8 章试点）： 2007 关键场景的底图刻意保持低细节（逆光、车窗反光、景深之外）；证据解锁后，叠加同机位的透明细节层（车票号、车窗上的字、她手里的东西）。它把「记忆会骗人」画了出来：历史没有被改写，只是看清了。无闪屏、无粒子。实现是底图加 1–3 层透明图，显隐只读取现有证据标记。
可借鉴的是方法而不是画风：《Unpacking》用物件的变化讲几十年人生，《Florence》用操作方式本身表达关系的亲疏。
3.3 品牌母题：信封与邮戳
整款游戏只需要一个反复出现的视觉母题，它能让本作不再像通用文字游戏模板：标题页、片段收束卡（邮戳）、结局卡、分享图、商店图标（信封一角加一个空着的邮票位）都用它。隐藏结局「余生未寄」的卡片是没有邮戳的信封（若与结局语义契合）。不发光、不加装饰。
3.4 阅读页：三态阅读＋年代皮肤
三态（节点增加可选字段 presentation、sceneId、skin；缺省取章节默认值，旧数据无需改动）：
生活流（默认，应占绝大多数节点）：上方场景窗（约占屏高三分之一，上滑时收缩成窄条），下方纸面长文。
场景帧（重要地点与对话）：场景窗展开，人物以背影或局部入画，仍是滚动文本。
关键时刻（每个片段不超过 1 次）：全屏物件特写或 CG，文字不超过 3 行，叠在渐变底上。
纸面起点值（1080×1920 设计稿，实机校准）：正文约 46px（三档 40/46/54），行高 1.75，左右边距 72px，段间距约 0.8 行；日间与夜间两种纸面。不用逐字打字机效果，段落整体淡入（150–250 毫秒）。

3.5 人生书桌的做法
合成而非整图： 固定约 60–70° 俯拍、单一光源（台灯，左上）；桌面底图与各物件分别生成透明素材，在引擎里合成并统一投影。这比整图生成再切分稳定得多，也让「书桌随章节变化」几乎零成本。
状态： 全程最多 6 个桌面状态，每次变化不超过 3 个物件。
热点： 不小于 130×130 设计像素（约 48dp），间距≥24px，避开屏幕边缘 48px 内的手势区。
规则： 不显示收集数量；未取得的物件不出现（不是灰色占位）；桌上的信永远是「继续阅读」；台灯光晕只做缓慢呼吸，不闪烁、不描边发光。

3.7 声音：低成本高回报
比美术先做一轮「环境声先行」：三套房间音（2037 家、2007 公交、书桌）加 8–12 个短音效（钥匙、纸张、翻面、MP3 按键、短信提示、车门气泵等），单声道低码率，总量控制在 3–4MB。关键对话允许无声。在第一次点击处解锁 Web Audio，失败则静默降级。不重生成已确认的人声。

3.9 文本质量：量化加滚动编辑
体验地图： 脚本从剧情 JSON 输出「章×片段」表：字数、预计分钟（按每分钟 400–500 字估算）、选择数、互动数、年代；标出连续多个节点既无互动也无场景变化的「荒漠区」。
文本体检： 统计高频短语与句式、段尾格言（「原来」「也许」「终究」一类）、「沉默」「窗外」「雨」等氛围套话、不同人物口头禅混用，输出命中清单交给真人。它只找线索，不替人下结论。
滚动编辑： 1–3 章在 rc.3 前锁文（美术依赖文本，先锁再画）；4–7 章在 rc.4；8–10 章在 rc.5。每条意见保留章节、节点 ID、原句、原因、建议（沿用策划书格式）。
人物语言指纹： 每个主要人物写 5 条「只有他或她会这样说」的句式，作为编辑与体检的依据。
前情一句话： 每个片段预写 1–2 句，给间隔几天回来的玩家。
3.10 结局、周目与回流
结局卡复用信件模板：每个结局一枚邮戳（日期加一句话），收进「抽屉」；分享图就是结局卡，不剧透。
二周目（可选）：书桌留下上一周目的痕迹（便签、折过的信角），不显示收集进度。
每个结局的尾声保留一段生活继续的内容，不浪漫化（沿用策划书原则）。
四、技术与性能约束
包体： 设计目标首包≤20MB（官方文档有 20MB 与 60MB 两种口径，取严）；章节资源走 Asset Bundle 按需加载，是否允许远程资源以空壳实测为准；包体须用 TapTap 打包工具产出。
字体： 正文用系统字体栈，标题用子集化字体；整套中文字体动辄数 MB，不要入包。容器内系统字体有差异，换行与行高必须实机核对。
长文本： 把「清空重建整块文本」改为「段落级节点加对象池」，只挂载视口附近的段落；用 Phase 0 的 profile 对比内存曲线。
长宽比： 设计稿 1080×1920，但验收覆盖 16:9 到 21:9 共 5 种比例；场景窗锚顶，文本区弹性伸缩。
存档： 新 UI 状态（字号、主题）放独立命名空间，不进剧情存档 schema；批注式记忆的视图状态优先由现有证据标记推导，不足时再加字段并写迁移；读取时忽略未知字段，保证发布后热修回滚不丢档。
中断： 监听切后台、锁屏与平台强制下线，做到段落级自动存档（防沉迷可能随时终止会话）。
回退： UI v2 做成视图层，v1 视图保留到 rc.5 稳定后再删；rc.2 打 baseline 标签，每个版本打标签。
视觉回归： 用 Playwright 对 12 个关键状态在 5 种比例下截图，存入 docs/shots/版本号/，由人眼审阅，不做像素比对门禁。

六、版本路线图
相对工作量（仅作排序参考，日历在 Phase 0 结束后再排）：Phase 0 小，Phase 1 中，rc.3 大，rc.4 大，rc.5 最大，1.0.0 中。
Phase 0 · 取证与前置验证（不发版、不动玩法）
目标： 用事实替换推测，把三个发现得太晚的风险前置。
工作： ①三台设备实机基线（首屏时间、第一章内存峰值、掉帧点、录屏）；②rc.2 空壳上传 TapTap 扫码自测（包体口径、登录、防沉迷、音频解锁、安全区、存档、字体）；③体验地图与文本体检；④玩家 5 秒测试与 10 分钟观察（3–5 人，作为 rc.3 对照基线）；⑤人物一致性盲测；⑥合规清单与素材原创证明包立项；⑦场景与物件清单、资产台账。
通过： 基线数据齐全；空壳能在容器内跑通；场景清单在预算内。
Phase 1 · 标准冻结
产出： 三张基准屏（人生书桌、2037 家庭阅读、2007 公交阅读）加决定面板变体；两套皮肤令牌；书桌分层规格；五个互动模板线框；美术规范（含禁止项与反向提示词）；仅需露脸角色的设定表。
做法： 先在引擎里搭灰盒（色块与文字，验证布局、热区、可读性），通过后再上终稿图。
通过： 5 秒测试中至少 4/5 的人能说出类型、年代、情绪中的两项；三屏并排明显属于同一游戏；缩到商店截图尺寸仍可读；与令牌表一致。
不做： 批量出图。
rc.3 · 门面与阅读层（第一章垂直切片）
范围： 合规首启流程 → 新玩家直入第一章、回访玩家进书桌；阅读页三态与两套皮肤；决定面板；设置（字号、音量、减少动态）；第一章全部视觉；三套环境声；段落级文本渲染；视觉回归截图。其余章节使用「年代皮肤加通用场景窗（4–6 张）」，不出现纯黑占位。
不做： 新互动、新玩法。
通过： rc.2 存档可读且章间恢复正常，自动化测试全绿；第一章 10 分钟观察中无人因界面困惑停顿 10 秒以上；性能不劣于基线（阈值待 Phase 0 校准，起点建议：首屏慢不超过 1.5 秒、内存峰值不超过基线 +30%）；5 种比例无遮挡溢出；至少 3 张可用商店截图。
回退： 回到 baseline 标签；低端机指标超阈且两轮优化无效，则降级为「纸面加通用场景窗」最小版。
rc.4 · 互动模板
范围： 五个模板与数据接口；先在第 1、2、8 章各接一遍，证明可复用；批注式记忆在第 8 章落地；灰盒到终稿。
通过： 每个模板单手可完成；切后台、锁屏、来电后可恢复；音频或图片失败时降级为文字、不阻断主线；证据规则有自动化测试（未读到末尾不发证据、不支持的证据不通过）；旧存档里已得证据在新视图中正确显示。
回退： 模板级开关，任一模板不达标则退回 rc.2 文本版，不阻断发布。
rc.5 · 全篇铺开与编辑
范围： 2–10 章按场景清单补图（不超预算）；8–10 章编辑收尾；人物语言指纹复核；六结局与二周目实玩；全篇音频；结局邮戳卡；（可选）周目书桌痕迹。
通过： 十章真人通读完成，问题台账关闭率≥95%，余项逐条评估；3–5 位玩家在 2–3 周内各通关至少一个结局，人物回忆测试达标；低端机跑完整章节内存无持续增长；六结局可达；没有退回占位界面的章节。
1.0.0 · 发布验收（功能冻结，只修缺陷）
合规包（资质、隐私、实名防沉迷视频、素材原创证明、AI 声明）；商店物料（图标≥512×512、含实机的截图、含游戏名的宣传图、≥15 秒视频）；全量回归；TapTap 真机。
首次提审的官方文档口径为 1–3 日，但仍预留至少一轮驳回返工时间。测试通过不等于平台批准，提审与上架由你决定。
1.1.0 及以后
依据真实玩家反馈再定：阅读排版、中断恢复、易读性、少量生活支线。不预设联机、AI 聊天、付费剧情。
