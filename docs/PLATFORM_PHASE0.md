# 平台前置核对

核对日期：2026-10-08。用户路线图涉及普通小游戏与H5适用性的推断，本文件区分官方页面、实际后台和仍待核实项目；不把上传成功写成可上架。原RC2已按授权上传现有游戏并给出二维码，不再创建条目或上传空壳。

## 官方公开页面与适用性

[小游戏介绍](https://developer.taptap.cn/minigameapidoc/quick-start/guide/minigames-intro/)区分普通小游戏与H5小游戏。当前目标后台只返回H5包体能力，因此普通小游戏SDK、打包和资质说明不能未经核对直接当作当前H5实现要求。

[创建小游戏](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)的资质表对仅有小游戏游玩方式写明由平台默认承担防沉迷；同时提供APK时规则不同。该页也列出包体登录接入与首包大小说明。它不支持“所有情况都由游戏额外再做同样的实名弹窗”的结论；本目标的登录与容器会话行为仍须实测。

[小游戏审核规范](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/review-standards/)另列20MB、登录、资质与素材证明等审核项目；大小文字与创建页不同。现阶段以20MB为项目预算目标，对H5目标的具体资格、打包和上线要求保留待后台确认，不自行承诺无版号可运营或无需资质。

[游戏物料要求](https://developer.taptap.cn/docs/en/store/release/publish/material/)要求实机玩法素材。概念稿和灰盒不能冒充正式游戏画面；届时从真实候选录屏和截图，记录版本、实际尺寸和素材去向。

## 前置问题台账

1. 当前H5容器：首次音频手势、录音自然结束、纸面字体换行、安全区、长文中断、后台与锁屏恢复、清缓存后存档边界。
2. 当前目标是否由平台处理登录/实名/防沉迷，游戏收到什么会话结束事件。先确认适用接口与真实行为，再接薄平台适配，不叠加假实名界面。
3. 平台部署端是否压缩JS/JSON、缓存与资源请求规则、是否允许独立章节资源加载；桌面gzip服务只能作对照。
4. 当前H5目标资料与资质页具体必填项，包括主体、备案、软著、原创证明、AI素材申报入口。未读取或未完成的项目不能打勾；敏感资质由开发者处理。
5. 工具商业条款、原创生成记录、人工编辑记录与平台认可分别核验。路线图中的AI标识法律概括未在本批独立法律核实；先保留来源与预留关于页说明，不把概要当合规批准。
6. 云存档仍是发布前评估项目。当前只有本地存档；没有确认平台接口、身份和冲突方案，不新增伪云同步或覆盖玩家原文。

不为以上待核项目抢先新增普通小游戏SDK、数据统计、联网或商业化。首批UI偏好采用独立命名空间，采样报告只在开发工具生成，正式玩家流程不偷偷收集测试指标。
