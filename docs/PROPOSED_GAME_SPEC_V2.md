# 第一章 项目总定位

## 1.1 游戏核心定位

《余生未寄》不是一款以反复选择选项为主要玩法的恋爱视觉小说。

它是一款以普通中国人的成长、爱情、婚姻、家庭与遗憾为主要内容的长篇人生叙事游戏。

玩家以周叙的视角，重新经历从2007年到2037年的重要人生片段。

玩家可以参与部分决定，但不能随意控制其他人的人生。

游戏的目标不是让玩家追求所谓的完美爱情结局，而是通过真实的生活经历，逐渐理解过去、理解身边的人，也理解自己。

**核心命题：**

> 我们怀念的究竟是那个人，还是和那个人在一起时年轻的自己？

**核心体验：**

让玩家感觉自己陪一个普通人经历了几十年，而不是一直点击按钮阅读剧情。

## 1.2 产品承诺

玩家进入游戏之后，应获得四种体验：

1. **生活的真实感：** 人物不是为了主线而存在，他们有工作、考试、家庭和自己的计划。
2. **时间的流逝感：** 玩家能从衣着、通信方式、生活条件、环境变化中感觉到年代前进。
3. **记忆的不可靠性：** 玩家曾坚信的过去，可能只是某个人所知道的部分事实。
4. **决定的长期影响：** 真正重要的选择不多，但它们会在很多年后留下痕迹。

## 1.3 核心差异化

相较于普通互动小说，《余生未寄》重点建立三种独特体验。

**第一：用生活塑造感情。**

不依靠连续表白、矛盾和煽情桥段制造情绪，而是通过公交、作业、照片、租房、工作、带孩子等日常事件建立人物关系。

**第二：玩家面对的是已经发生的人生。**

2007年的故事不会因为2037年的记忆重构而被魔法般改变。记忆变化的是理解，而不是历史事实。

**第三：初恋与婚姻不构成简单的对立。**

许知夏拥有自己的后来人生，程安然也不是阻碍主角追寻真爱的工具人。

游戏不设置单一正确的情感答案。

## 1.4 用户定位

目标用户建议为18岁以上、偏好长篇故事、细腻人物关系、生活题材、阅读与轻交互的玩家。

第一优先级不是追求所有休闲小游戏用户，而是吸引愿意阅读、能够接受慢节奏、对生活经历有共鸣的玩家。

传播重点应该是故事、人物与遗憾，而不是夸张的多结局噱头。

# 第二章 游戏世界与故事基础

## 2.1 时间线

| 年份        | 主角人生   | 主要故事            |
| --------- | ------ | --------------- |
| 2007      | 17岁    | 周叙与许知夏在17路公交相识  |
| 2009      | 19岁    | 高中毕业，许知夏写下给未来的信 |
| 2009—2013 | 19—23岁 | 大学、异地、家庭与工作压力   |
| 2013      | 23岁    | 工作决定和车站分别       |
| 2017      | 27岁    | 周叙认识程安然         |
| 2020      | 30岁    | 周叙与程安然结婚        |
| 2021      | 31岁    | 女儿周满出生          |
| 2037      | 47岁    | 周叙收到迟到的信，重新审视过去 |

**必须锁定的时间事实：**

2009年写的信，在2037年已有28年历史。

2013年的分手，距离2037年是24年。

两个时间跨度不得在对白、照片、宣传文案和配音中混淆。

## 2.2 主要人物

### 周叙

青年时期内向、要强，喜欢把事情提前规划好。

他不是坏人，也不是完美恋人。

他的核心缺点是习惯替别人做决定。

中年后的周叙有工作、家庭、父母和女儿，生活不能被表现成仅仅围绕初恋转动。

### 许知夏

活泼、敏感、有摄影爱好，也有自己的脾气、判断与计划。

她可以任性，会误会，也会做不成熟的决定。

她在2013年后继续生活，不是一直停留在青春时代等待周叙。

成年后的她拥有独立的工作、家庭与社会关系。

### 程安然

务实、直接、有自己的职业能力与理想。

她与周叙共同生活多年，经历过买房、租房、工作调整、生病、养育孩子和日常家庭分工。

不把她设计成故意冷淡、控制欲强或外貌逊色的妻子。

### 周满

2037年16岁，有朋友、学业、自己的情绪和人生问题。

她不是专门负责替父亲说出人生哲理的角色。

### 陈野

周叙的高中朋友。

有自己的感情、工作与生活发展，既是故事人物，也是后来回忆的重要证人。

他提供的只能是自己确实知道的事实。

# 第三章 玩法总体设计

## 3.1 核心玩法比例

建议按照体验目标控制为：

| 内容类型    | 体验目标 | 作用         |
| ------- | ---- | ---------- |
| 连续生活叙事  | 70%  | 人物、情节、时间变化 |
| 生活与旧物互动 | 20%  | 增强在场感和证据发现 |
| 重大人生决定  | 10%  | 影响长期关系和结局  |

这些是设计目标，不是要求每10个节点必须出现一次选择。

有的片段可以完全没有选择。

## 3.2 核心循环

**经历生活 → 发现变化 → 接触物件 → 获得新信息 → 理解旧事 → 做出少量重要决定 → 继续生活。**

游戏采用轻交互，不加入战斗、经营、抽卡、体力或养成数值面板。

## 3.3 长篇阅读系统

普通生活剧情以连续段落展示。

每一个阅读片段必须包含具体内容，而不是用物件列表和重复感叹凑长度。

优先写：

- 人物想做什么；
- 过程中发生了什么；
- 他人如何回应；
- 一件事情产生了怎样的日常变化。

阅读系统需要支持自然滚动、自动记录阅读位置、字号调整和阅读中断恢复。

每个 Story Segment 的目标体验为3—8分钟，但正式时长必须由真实玩家阅读测量，不能以脚本点击次数证明。

## 3.4 人生决定系统

普通交谈由人物自然完成。

只有真正影响长期关系、后续行为和人生理解的节点，才出现“决定”。

重大决定应该有三个层次的结果：

**即时结果：** 眼前的人如何回应。

**中期结果：** 后面某件生活事件怎样改变。

**长期结果：** 多年后相关人物如何重新提及这段经历。

不允许只有隐藏数值变化，没有实际文字承接。

## 3.5 关系系统

关系属性仅在内部记录。

绝不在正式界面出现“许知夏好感度87”“程安然信任值65”等条形图。

关系表现通过短信频率、对话方式、主动联系、沉默、共同承担事情等方式体现。

## 3.6 记忆重构系统

记忆状态分为：

1. 残缺
2. 出现矛盾
3. 重新理解
4. 完整

核心证据包括信件、照片、录音、日期、短信、朋友证词等。

证据只能证明它实际支持的事情。

不能因为玩家打开了一张照片，就直接知道所有人的真实想法。

记忆重构允许玩家对照不同来源，重看曾经的场景，并了解以前被忽略的信息。

不得使用闪屏、爆炸特效、碎屏和大量粒子作为记忆重构的主要表现。

# 第四章 十章正式内容规划

现有十章、60片段和467节点是本次升级的基础，不重新推翻。

| 章节            | 主要内容                     | 体验重点      |
| ------------- | ------------------------ | --------- |
| 第一章 那封迟到的信    | 2037家庭、旧纸箱、迟到的信、MP3、公交回忆 | 生活真实与悬念   |
| 第二章 十七岁的夏天    | 校园、公交、摄影、作业、朋友           | 建立人物熟悉感   |
| 第三章 我们以为会永远   | 恋爱、家庭、毕业、未来约定            | 让玩家相信这段感情 |
| 第四章 两座城市      | 大学、异地、联系变化               | 日常积累的距离   |
| 第五章 未来开始有价格   | 工作、家庭责任、双方规划             | 选择与沟通     |
| 第六章 那天我们都没有回头 | 车站分别、遗漏的信息               | 记忆与现实差异   |
| 第七章 后来的人      | 程安然、婚姻、孩子、家庭             | 另一段真实生活   |
| 第八章 记忆会骗人     | 多份证据、旧事重读                | 重构理解      |
| 第九章 如果现在去见她   | 联系、坦白、见面边界               | 成年人的责任    |
| 第十章 余生未寄      | 日常继续、家庭关系、写给自己的信         | 接受没有走过的人生 |

## 4.1 编剧硬性要求

每章必须具有主事件、日常生活、小事件、人物独立生活线和关键节点。

不能把每个生活事件都写成一段人生哲理。

不得让女儿成为道理输出者、陈野成为资料库、许知夏成为完美初恋、程安然成为现实生活的负面代表。

真实生活中的结束，应由多年累积形成，而不是一次普通回答导致分手。

## 4.2 剧情审读制度

正式发布前应进行全篇真人阅读，逐条标记：

- 人物是否有真实说话方式；
- 是否出现不合时代的词语与物件；
- 2007—2037年的人物年龄和日期是否一致；
- 重大决定是否在后文得到承接；
- 是否有作者替玩家直接讲道理；
- 普通生活是否过于重复；
- 人物在不同年龄时的性格是否连续；
- 所有互斥分支是否自洽。

每条问题必须保留章节、节点ID、原句、问题原因和修改建议。

# 第五章 正式UI与交互设计

本章是V2.0最重要的升级内容。

当前工程虽然具备基本功能，但主要依靠深色背景、统一文字和矩形按钮。

正式版本必须让视觉与生活叙事对应起来。

## 5.1 总体UI原则

**现实、克制、清晰、生活化、具有质感。**

不使用华丽恋爱手游界面。

不使用科幻系统UI。

不把阅读游戏设计成复杂的移动应用仪表盘。

文字优先清晰，场景优先可信，操作优先自然。

## 5.2 首次进入流程

首次打开游戏：

工作室标识短暂出现 → 雨夜环境声 → 周叙回家 → 2037年的普通家庭 → 旧纸箱出现 → 游戏正式开始。

不要求玩家先通过复杂的开始菜单。

工作室标识和开场过渡应简短，并允许再次进入时跳过。

## 5.3 返回用户主页：人生书桌

**首页采用一张完整的生活场景，而不是几个孤立的按钮。**

建议场景为2037年的书桌。

书桌上可逐步出现信封、照片、旧MP3、毕业册、抽屉及其他有剧情意义的物件。

对应功能如下：

| 视觉物件     | 实际功能        |
| -------- | ----------- |
| 桌上的信     | 继续阅读        |
| 旧相册      | 已发现的照片      |
| 旧MP3     | 已取得的录音      |
| 毕业册      | 人生轨迹        |
| 抽屉       | 已完成的结局      |
| 角落的小设置入口 | 音量、字号、存档说明等 |

只有玩家已经取得的内容才可进入。

首次使用时不显示完整收藏数量，避免变成收集任务。

书桌应随着章节推进发生细微变化，而不是每次回主页都重新装饰。

## 5.4 故事阅读界面

采用两种相互协调的表现方式。

**普通生活阅读：**

完整可滚动文字、清晰标题、舒适行距、明确人物称谓和充足留白。

**重要场景阅读：**

场景背景出现，角色局部立绘或人物动作配合文字；必要时隐藏部分文本区域，突出人物和环境。

不让所有场景都强制出现立绘。

## 5.5 决定界面

出现重大决定时：

背景保持当前场景，只弱化不重要内容。

选项采用自然语言。

按钮区域要大，便于单手使用。

不用道德颜色、不显示“正确决定”、不显示属性变化。

一旦作出决定，先展示当前人物实际反应，然后继续剧情。

## 5.6 旧物调查界面

2037年的纸箱不再只显示文字菜单。

正式界面应有真实箱体和物件的相对位置。

点击物件可以放大查看。

已检查物件可保持原位，只发生轻微状态变化。

玩家随时能返回当前调查界面。

不能靠连续点相同物件获取属性奖励。

## 5.7 旧手机界面

2007—2013年使用符合年代的通信形式。

2037年使用现代移动通信界面。

全部设计原创，不直接复制微信或其他通信软件的具体界面。

短信需要保留发送时间、前后文和实际阅读顺序。

不能提前显示角色尚未知晓的信息。

## 5.8 照片界面

照片与场景插画必须有明确区别。

照片是故事里的实物，应保留快照属性。

玩家能查看正面、背面、日期和字迹。

2009年刚拍出的照片与2037年保存多年的同一照片，人物内容必须一致，纸张状态可以不同。

## 5.9 信件界面

信封、信纸、折痕和手写内容应作为独立视觉元素。

拆信动画短促、自然。

长篇内容需要支持滚动与断点保存。

没有真实读到末尾时，不得直接授予“已读完整信件”的剧情证据。

## 5.10 MP3界面

旧MP3应有符合当时年代的材质和尺寸。

按钮包括播放、暂停、继续、查看文字。

音频无效或设备不允许播放时，应使用文字替代而不阻断主线。

不得在播放尚未完成时提前记录完整来源证据。

## 5.11 设置与无障碍

至少提供字号调整、背景音量、语音音量、文字记录、减少动态效果、存档状态与错误恢复。

安全区必须适配刘海屏、底部手势区以及不同长宽比。

重要操作不能依赖过小的热点。

# 第六章 美术风格正式规范

## 6.1 总体风格

**中国城市现实主义 × 克制的怀旧电影感 × 半写实叙事插画。**

不能简单等同于所有图片都做成写实摄影。

不同类型的美术资产需要不同的功能。

| 资产类型   | 风格要求          |
| ------ | ------------- |
| 场景背景   | 半写实、普通生活、统一笔触 |
| 人物立绘   | 写实比例、轻度插画化    |
| 剧情照片   | 真实快照质感        |
| 物件插画   | 清晰材质、实际年代可信   |
| UI背景   | 低装饰、高可读性      |
| CG重点画面 | 保持与人物和场景统一的画风 |

## 6.2 年代视觉

**2007—2013年：**

自然日光、旧公交、普通高中、旧教室、早期手机、大学宿舍、普通住宅和街景。

不刻意把所有青春场景做成金黄色。

**2017—2037年：**

现代城市、普通办公与住宅环境、家庭用品、工作文件、厨房、医院、车站。

不刻意把中年生活做成阴冷灰暗。

色彩变化必须来自时间、天气和场景情绪，而不是用滤镜判断谁的生活更好。

## 6.3 角色统一规范

正式绘制前先制作角色视觉设定表。

每人至少锁定面部比例、发型、肤色范围、常见衣着、标志性特征和不同时期的自然变化。

周叙17岁与47岁必须能辨认是同一个人。

许知夏年轻与成年阶段应有稳定的面部身份。

程安然必须与其他女性角色采用同一审美标准，不故意贬低。

周满按16岁真实学生设计，不使用成年化或偶像化造型。

人物不要求每张图都完美正脸、对称或表情精致。

## 6.4 图片资源的当前问题

现有工程有四张已使用的照片资源：

- 毕业照片旧版；
- 毕业照片新拍版；
- 2035年家庭照片；
- 2010年旧街照片。

这些资源属于剧情照片，不能承担全游戏场景美术的职责。

是否保留每张照片，需要结合实际游戏显示效果、人物身份一致性和美术标准判断。

不以生成成功或自动审美评分作为最终通过依据。

## 6.5 首批必须重做的视觉基准

正式大批量制作前，只需要完成三套关键视觉基准。

**第一套：人生书桌。**

验证UI设计、物件布局、光线、操作热点和生活气息。

**第二套：2037年雨夜家庭。**

验证现实线、家庭空间、人物视觉与文字阅读的关系。

**第三套：2007年17路公交。**

验证青春线、年代物件、许知夏出场和回忆氛围。

三套确认以后，再批量扩展其他场景。

## 6.6 资源生产方式

原创素材使用 Image 2 或其他确认可商用的制作方式。

每个资源需求必须记录：

资源ID、所在章节、用途、画面描述、构图、灯光、人物设定、尺寸、禁止内容、来源、审查状态及最终采用版本。

不把生成的第一张图片直接加入正式工程。

所有正式图需要通过：

人物一致性 → 时代准确性 → 构图适用性 → 手机显示 → 去AI感 → 原创及许可复核。

## 6.7 三张核心场景的制作提示词

### ART-BG-001：2037年雨夜家庭

中国普通城市家庭，2037年9月雨夜，住宅餐厅与客厅相连，普通现代家具、墙角文件袋、餐桌水杯、厨房暖灯、窗外雨水，整体生活化，空间布局可信，半写实叙事插画风格，轻微真实笔触，普通室内光照，不夸张电影灯光，不出现人物，不添加文字。竖屏构图，预留可读文字的安全区域。

**禁止：** 豪宅、电影海报构图、夸张蓝橙光、科技屏幕、霓虹、浓雾、粒子、过度锐化、虚假文字。

### ART-BG-002：2007年17路公交

2007年中国普通中小城市公交车内部，旧式座椅、车窗、扶杆、普通乘客生活痕迹、略显拥挤但结构合理，夏末自然光，真实旧车材质，半写实叙事插画风格，普通学生能够乘坐的线路氛围，竖屏叙事构图，预留人物与对白位置。

**禁止：** 日本动漫巴士、现代新能源公交内饰、过度唯美夕阳、浪漫粒子、科幻材质、旅游广告海报风、乱码文字。

### ART-BG-003：2037年人生书桌

中国普通中年男性家中一张使用多年的书桌，浅旧木纹，普通台灯，信封，旧毕业照片，小型旧MP3，毕业册和家庭生活物件，摆放自然，略有使用痕迹但不过分脏乱，暖色室内灯与窗外较冷夜色形成自然对比，半写实高品质叙事插画，主要物件清晰可辨并适合点击交互，竖屏构图。

**禁止：** 豪华复古书房、侦探解谜游戏道具堆积、悬浮按钮、发光物件、复杂仪式感、胶片滤镜叠加、文字标题、AI式精致摆拍。

提示词只是制作输入，不能替代角色设定和人工审图。

# 第七章 声音设计

## 7.1 声音原则

声音必须像生活的一部分，而不是每句对白都配情绪音乐。

普通家庭场景允许只有厨房声、空调声、钥匙和脚步。

2007年公交有发动机、车窗和车辆停靠声。

雨夜可以有较轻的环境声。

重要对话允许留白和沉默。

## 7.2 人物声音

现有第三版虚构角色普通口语音色已经作为当前确认基准。

后续不擅自恢复被否定的动漫式、偏甜或播音式声线。

重要的是自然接话、停顿、语速和实际环境，不靠哭腔或降调滤镜制造情感。

## 7.3 配音范围

首发版不要求全游戏强制全语音。

优先配重要录音、关键人物声音和少量必要剧情节点。

其余长篇阅读可以依赖环境音和文字完成。

这样既控制成本，也避免配音破坏生活流叙事的自然节奏。

# 第八章 六个结局设计

保留现有六个正式结局。

| 结局        | 核心表达             |
| --------- | ---------------- |
| 好久不见      | 成年后真实见面，理解彼此已经改变 |
| 不要再见了     | 有机会见面，但选择保留距离    |
| 后来我才懂     | 理解过去并接受事实        |
| 如果那年      | 仍有未能解开的遗憾        |
| 谢谢你陪我走到这里 | 理解共同生活的重量        |
| 余生未寄      | 重新理解自己的人生，隐藏结局   |

结局不能设计成奖励排名。

隐藏结局必须保留已有的多周目、真实证据、核心记忆和实际行为条件。

不得通过随机数、高分或广告直接解锁。

结局后的生活不能全部被浪漫化。

不同结局需要留有自然的生活延续。

# 第九章 数学与系统规则

只使用服务剧情和运行稳定性的数学函数。

## 9.1 隐藏属性

维持以下属性：

nostalgia、reality、regret、understandingXia、understandingPartner、selfReflection、honesty、avoidance。

范围0—100。

更新公式：

`x_new = min(100, max(0, x_old + delta))`

## 9.2 分支判断

优先采用事实标记与逻辑条件。

`AND / OR / NOT`

没有读完的信不能被当作已经阅读。

没有实际发生的会面不能凭高分生成。

## 9.3 结局判定

先确认硬条件，再通过小幅线性加权评分选择符合事实的结局。

相同分数采用固定顺序。

禁止随机决定人生结局。

## 9.4 阅读与资源管理

阅读位置保留滚动进度。

资源按当前片段和下一片段加载。

美术增加后应考虑图像压缩、章节资源隔离、旧资源释放与低性能设备内存。

不得为了形式完整加入复杂调度系统。

不为增加广告观看次数而故意阻断阅读。

留存主要来自人物命运、记忆真相和多结局。

可设计克制的结局分享图，但不得自动剧透。

玩家分享的是自己对故事的理解，不是排行榜和数值成绩。

# 第十三章 商业级验收标准

## 产品

玩家应能从头到尾正常经历十章和六结局。

第一章必须在短时间内建立人物、生活环境与迟到的信的悬念。

各章之间的阅读节奏不能只有文字量指标，还应有真实玩家测试。

## 视觉

场景、人物、物件、UI必须属于同一设计体系。

2007和2037的视觉差别自然可辨。

正式界面不能存在开发占位图、无意义按钮或未完成交互。

## 剧情

人物具有独立生活，重大选择有后果。

日期、年龄、物件来源和角色事实一致。

六结局成立条件真实可靠。

## 技术

Cocos Creator 3.8.8正式构建通过。

无阻断脚本错误、资源加载错误和严重存档丢失。

历史存档兼容，二周目有效。

主要手机尺寸可正常阅读与交互。

## 平台与合规

正式资源具有明确来源与使用许可。

全部内容符合实际发布平台现行要求。

TapTap运行和提审另行验收，不得只用Chrome浏览器通过来代替。

# 第十四章 去AI感总审查

所有新增内容必须回答：

**它有没有让人物更真实？**

**有没有让情绪更准确？**

**有没有让操作更自然？**

如果三个问题都不能回答，就不要增加。

重点审查：

- 每个人是否都在说过于完美的句子；
- 每张图是否都像精致广告；
- 每个场景是否都用相同构图和光线；
- 每个交互是否都需要发光提示；
- 是否把普通物件变成解谜道具；
- 是否为了表现商业级而加入大量没必要的系统；
- 是否为了延长游戏而堆叠重复生活描述；
- 是否把遗憾描绘成唯美、绝对正确或值得牺牲现实责任的事情。

所谓高级感不等于更复杂。

真正的完成度，是每一个存在的设计都有必要。

# 最终产品定义

**《余生未寄》是一款让玩家陪伴普通人经历几十年人生的现实叙事游戏。**

它可以讲爱情，但不只有爱情。

它有遗憾，也有工作、婚姻、孩子、父母、朋友以及那些没有被记录的大量普通日子。

我们要让玩家记住人物，而不是记住按钮。

记住那些真实发生过的小事，而不是记住不断弹出的系统提示。

真正的结局不是选出一条最好的生活，而是理解：

有些人曾经认真爱过，后来各自生活；而已经走过的人生，同样值得认真对待。
